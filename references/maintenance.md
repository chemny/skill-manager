# 维护与恢复边界

管理核心是 `scripts/maintenance.py`，CLI 和 `/api/maintenance` 都调用它。继续使用现有 SQLite，没有新增框架或依赖。

## 状态解释

- `latest`：本次下载的确认来源/ref与本地管理文件一致；额外本地文件仍可能存在。
- `update_available`：存在可信基线的远端差异，或远端版本较新且内容有差异。执行前仍可能需要处理本地冲突。
- `local_modified`：与上次通过此工具安装的基线不同。
- `baseline_unknown`：有差异，但不能证明只是远端更新；先检查本地内容。
- `local_ahead`：本地声明版本更高，不自动降级。
- `source_unknown` / `check_failed`：未绑定来源或检查失败，不显示最新。

GitHub 内容下载固定到解析得到的 commit，预览暂存以后不再拉取分支。计划有效期24小时，不复用同名项的远端缓存。未知子目录要求绑定精确路径，不按同名仓库自动猜选。

## 操作与回退

`apply` 使用进程间 OS 锁，检查目标、已知引用、源与暂存指纹，并先验证备份。目录替换先在目标旁准备内容，再用重命名切换；异常时恢复原目录。停用/启用保持登记 ID，扫描也尽量识别同文件系统中的已知目录移动。不承诺跨文件系统外部复制或重装仍保持原 ID。

删除用可恢复区保存原内容和链接，不删除使用证据。备份索引关联操作 ID，并记录原位置、时间、清单、SHA-256、大小和权限。恢复重新校验备份并预览冲突，不执行技能中的任何脚本。

中断后：

1. 查看 `history` 中 running 条目，保存其 ID；不要自行删除暂存和持有原目录。
2. 运行 `recover-operation ID --yes`。如果最终内容完整则记录完成；如果只有持有原目录则回退。
3. 如果目标也出现未知变动，恢复会停下，让你保留两份内容后处理。失败/中断不能被当成已完成。

运行中断恢复后的 registry/source 状态必要时重新 `scan` / `check-updates`。跨文件系统的隔离移动失败时不自动降级成不安全删除；按报错处理。

## 空间、证据和旧记录

清单统计逻辑大小与分配块估算；硬链接、共享目标去重。APFS 压缩/克隆和其他进程活动会影响实际空闲空间，因此执行后的文件系统空闲变化不是精确承诺。

`plans` 列暂存；放弃的计划用 `discard-plan` 释放。可恢复区和备份保留到你主动清理，没有自动到期删除。旧目录备份缺少验证清单，单独列为未验证，不伪造可信恢复入口。

日志只保存命中路径、来源、事件时间和会话线索，不保存聊天全文。证据覆盖始终保守标为 partial；对任何窗口的零记录都不宣称闲置。扫描忽略隐藏备份，旧登记不删历史。旧版本曾用 mtime 推断的历史记录不再作为新的确定证据，但仍保留旧数据供核对。

## 开发验证

```bash
python3 -m unittest discover -s tests -v
```

文件变更演练必须使用临时目录/临时 `ASM_HOME`。真实库只扫描和读取。当前没有客户端代码；GitHub 推送/发布是另外的用户授权任务。

## Web 操作

Web 默认入口 `/manage`，旧安装/来源界面为 `/legacy`。操作点选清单中的对象，不按同名项自动替换；共享根入口可点选其真实源，但写操作影响全部已知引用。

预览、历史和备份可在页面中选择。执行前有确认对话框，核心继续校验24小时有效期、目标指纹、来源指纹、保护状态和已知引用。恢复冲突须明确允许覆盖；永久清理另行确认。

Web 任务一次一个，在服务进程内运行。关页面不取消，刷新可重新连接；主动停止服务会拒绝尚在运行的任务。进程被杀死或机器重启后，任务进度可能丢失；持久操作历史、预览和备份仍需核对，页面不自动重试写操作。

列表备份状态仅说明创建时已校验，不能证明当前完整性；单项“校验”和恢复会重新核对。技能变更后清除相关引用的旧更新检查，需重新检查来源。共享目标占用与本入口占用分别显示，汇总去重。开发对接见 [Web API](web-api.md)。
