# 项目空间清理

Web 后台的“空间清理”管理 Agent 项目和生成文件，与 Skills 安装目录的扫描分开。

## 使用流程

1. 点击右上角“扫描项目”，选择 Agent 和项目。默认保留上次勾选，可以排除项目；取消弹窗不保存改动。
2. 扫描只读取目录条目、文件大小和分配块，不读取项目正文、不计算哈希、不调用模型 API。项目清单按占用排序，重叠目录和硬链接不重复计入。已单独登记的子项目从父目录统计中扣除，父目录显示“其他文件”。
3. 选择项目后点击“分析选中项目”。进度显示在对应行内，刷新页面可以继续查看后台任务。分析检查缓存和内容完全相同的素材，保留原文件。
4. 打开“清理建议”，查看清理内容、文件数、空间和删除影响。默认不选择任何清理项。
5. 用户选择并确认后才移入现有回收站。移入前重新检查目录、文件指纹和重复组的保留副本；发生变化的文件保留。
6. 左侧“回收站”统一展示 Skills、备份和项目文件，可以按类型筛选。项目文件可以恢复到原位置，遇到同名文件不覆盖；只有再次明确确认永久删除后才删除回收文件。不自动清空或重试写操作。

## 项目位置

- Codex：线程数据库中的工作目录、配置中的项目路径和 `generated_images`。遵守 `CODEX_HOME`。
- Claude Code：本机 `.claude.json` 中的项目路径。
- Cursor、Windsurf：本机 workspaceStorage 的工作区元数据。
- OpenClaw：本机配置中明确登记的 workspace。
- 仅发现 Agent 目录、不足以确定项目位置时，不猜测项目路径。Hermes 暂只显示识别状态。找不到的项目可以通过文件夹选择器补充登记。

“重新扫描”只更新已经加入的项目；再次点击“扫描项目”才会重新识别 Agent 记录中的新增项目。移除勾选只修改扫描范围，不删除项目。

已知工作区中的 inbox、projects、outputs 和日期目录会按目录结构拆出独立项目。只检查目录名称、类型及项目标识，不读取正文；不把项目的 assets 等普通子目录拆成项目。父子目录仍互斥统计，排除的子项目也不会通过父目录重新进入扫描。

## 清理边界

缓存建议仅包含超过 7 天且存在对应源码的 Python 字节码；无源码缓存保留。重复素材先用 SHA-256 校验相同内容，每个独立项目至少保留一份，原始输入和参考素材优先保留。

批量分析结束后，在本次选中的项目之间核对同内容文件，复用已校验的哈希并检查文件变化。Codex 生成图片可以使用项目中核实的副本作为保留副本；其他独立项目不因跨项目重复而失去自己的唯一副本。跨项目结果绑定项目范围和扫描版本，重新分析后旧建议失效。移动前再次检查两侧目录、指纹和完整内容哈希，保留副本变化时不移动文件。即使内容重复，删除原路径仍可能影响历史报告、对话或预览，因此列明影响，由用户决定。

源代码、模型权重、3D 模型、文档成品、原始输入、参考素材、凭证、数据库、系统和应用目录、已登记 Skills、硬链接以及未下载的云端文件不作为清理候选。目录扫描不跟随软链接，可信项目入口的别名先合并。图片和视频仅在已核实重复时提供建议；文件旧、目录名包含 backup 或缺少引用都不是删除依据。

已从 glTF、OBJ 或材质文件中识别的贴图依赖与模型一起保留。自定义 Python 运行环境中的 site-packages、dist-packages 同样属于依赖环境；当前保护规则也会过滤已有扫描记录，不能通过旧建议绕过保护。

空间统计最多运行 300 秒，超时、停止或无法读取时保存部分结果，不能冒充完整空间。单个项目分析由独立进程执行，最多 60 秒；本地哈希预算为 4 GiB，跨项目额外读取预算为 8 GiB，批次总计最多 180 秒。未完成的项目可继续分析，继续时仍与此前已完成的同批项目比较。枚举、引用或哈希没有完成时显示“部分结果”，未核对文件保留；旧策略与不同项目边界的结果不能继续用于清理。APFS 压缩、克隆、硬链接和其他进程会影响最终空闲空间，表中占用不是精确的可释放承诺。

## 可复用的分析规则

- 空间枚举、重复内容校验、路径引用检查分别记录完成情况。只有要求检查的阶段均完成，才报告完整结果；不能用空间统计完成代替引用检查完成。
- 引用检查围绕实际候选素材和缓存建立路径索引，解析引用文件相对路径、项目相对路径、绝对路径及本地 file URI，处理 JSON 转义与 URL 编码。精确比较规范化路径，不用同名子串推断引用。动态拼接、外部项目及二进制文档的引用不在完整证明范围内，未发现引用不代表未使用。
- 大文本分块读取，优先检查模型材质声明、报告与清单。设置时间和读取预算，保存文件指纹、候选路径集合、检查版本、读取位置和已发现引用。再次分析复用已完成结果、继续未完成部分；文件或候选范围变化则作废缓存。超限、离线、读取失败与文本解码异常分别记录，不静默忽略。
- 重复内容只能证明字节相同，不能证明路径可删除。每个独立项目保留必要副本，原始输入、模型与材质依赖保留。未核实部分不能作为默认安全清理项。
- 移入前重查候选及保留副本的目录、文件指纹和完整哈希。用户明确选择、确认后才移入回收站；不自动删除。规则描述与实现能力必须一致，不将单次案例、目录或可调阈值写成通用保证。

当前实现：分块路径提取与有界重叠处理 JSON 字符串、HTML/Markdown、代码文本和模型声明；SQLite 缓存支持后续分析续查。覆盖字段包含各阶段状态、检查数量、本次读取量、缓存命中量及每个未完成文件的原因和位置。引用“完成”仅指当前项目内已枚举的支持文本，不代表已证明所有外部引用不存在。

## 验证要求

引用检查须覆盖大文本、跨块路径、相同文件名的不同目录、编码路径、缓存续查和失效、读取预算及异常；未完成时不得冒充完成。真实项目验证只读，移动、恢复及永久删除使用临时测试文件。

Python 覆盖范围、重叠去重、文件变化、保护目录、明确确认、恢复冲突与回收文件校验。`tests/browser_project_space.cjs` 用临时目录验证从扫描、批量分析、建议、移入、恢复到永久删除的完整交互，以及刷新恢复和窄窗口单行布局；不会扫描或修改真实项目。
